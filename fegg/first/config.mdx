# Settings

## Basic settings

The defaults are in `htdocs/_fegg/core/config/settings.php`. Do not edit that file (it is replaced on update). Put the values for your project in **`htdocs/_fegg/site/config/settings.php`**.

The core file is loaded first, then the site file. Only the keys the site file sets are changed, so write one key per line and never reassign the whole array (`$settings = array(...)` would drop the defaults).

```php title="htdocs/_fegg/site/config/settings.php"
<?php
defined('FEGG_CORE_DIR') || exit;

// Run mode  1: running, empty: under maintenance
$settings['run_mode'] = '1';

// Maintenance page URL
$settings['maintenance_page_url'] = '';

// Developer IP addresses (multiple allowed)
$settings['developer_ip'] = array('192.168.65.1', '203.0.113.10');

// Basic authentication scope (0: none, 1: whole site, 2: partial)
#$settings['basic_auth_scope'] = 0;
#$settings['basic_auth_user'] = '';
#$settings['basic_auth_password'] = '';
```

| Key                    | Default                         | Remarks |
| :--------------------- | :------------------------------ | :------ |
| `run_mode`             | `'1'`                           | `'1'`: running. Empty: under maintenance. During maintenance every request that does not come from `developer_ip` is redirected to `maintenance_page_url`, or gets a short maintenance message when it is empty. |
| `maintenance_page_url` | `''`                            | Redirect target during maintenance |
| `developer_ip`         | `array()`                       | Requests from these IP addresses run in developer mode (see below) |
| `default_language`     | not set                         | Language code used when none is detected, e.g. `'ja'`. Only for multilingual sites |
| `support_language`     | not set                         | Supported language codes, e.g. `array('ja', 'en')`. Only for multilingual sites |
| `basic_auth_scope`     | `0`                             | `0`: no Basic authentication. `1`: every page rendered by Fegg. `2`: only where the controller calls `$this->basicAuth()` |
| `basic_auth_user`      | `''`                            | Basic authentication user |
| `basic_auth_password`  | `''`                            | Basic authentication password |
| `template_dir`         | `site/template`, `core/template` | Template directories, searched in this order |
| `template_ext`         | `'tpl'`                         | Template file extension |
| `template_cache_dir`   | `site/data/cache/template`      | Compiled template cache |
| `global_config_dir`    | `''`                            | Optional directory searched by `loadConfig()` before `site/config/`. End it with `/` |

Read a setting from a controller with [`$this->getSetting()`](../basic/others/config/getsetting.mdx).

### Developer mode

When the request comes from an address in `developer_ip`, Fegg runs in developer mode (the constant `FEGG_DEVELOPER` is `'1'`):

- PHP errors are displayed.
- An uncaught exception shows the message, the file and line, the template line (`Template: <file>.tpl:<line>`), the stack trace and `$this->page`. Other visitors only get an HTTP 500. In both cases the error is written to the PHP error log.
- The 404 page shows which controller file Fegg tried to load.
- The site stays reachable during maintenance (`run_mode` empty).

Keep `developer_ip` limited to your office and local development addresses.

## Database

The connection is set in **`htdocs/_fegg/site/config/database_config.php`**. By default it is a SQLite file at `htdocs/_fegg/site/data/db/db.db`.

```php title="htdocs/_fegg/site/config/database_config.php"
<?php
defined('FEGG_CORE_DIR') || exit;

// SQLite file path. The FEGG_DB_PATH environment variable overrides it
$_sqlite_path = getenv('FEGG_DB_PATH') ? getenv('FEGG_DB_PATH') : FEGG_SITE_DIR.'/data/db/db.db';

// Production environment
if (false) {

    // Master database (a single server)
    $database_config['master'] = array(
        'dsn' => 'sqlite:'.$_sqlite_path,
        'username' => '',
        'password' => ''
    );

    // Slave databases (multiple servers allowed)
    $database_config['slave'][] = array(
        'dsn' => 'sqlite:'.$_sqlite_path,
        'username' => '',
        'password' => ''
    );

// Development environment
} else {
    // ... same keys for the development environment
}
```

- `master` is used for writes and `slave` for reads. With SQLite both point to the same file.
- Replace `if (false)` with a condition that detects the production server when the two environments use different databases.
- If the server allows it, put the SQLite file **outside the document root**: change `$_sqlite_path`, or set the environment variable `FEGG_DB_PATH`.

Tables are defined in YAML files (`core/config/database/` for the CMS tables, `site/config/database/` for the project's tables) and created or changed with `./fegg-cli migration` (see [fegg-cli](./cli.mdx#migration)). Every table needs the columns `valid`, `created` and `modified`.

## Other files in `site/config/`

| File                  | Remarks |
| :-------------------- | :------ |
| `route.php`           | URL routing (see [URL](../basic/url.mdx#routing)) |
| `site_info.php`       | Site title, description, OGP image, `picture` breakpoints, ... Loaded by the base controller and available in templates as `$site` |
| `category_info.php`   | Labels for categories and the CMS visibility states. Loaded by the base controller into `$this->config['category_info']` |
| `cms_menu.php`        | CMS side menu. Add one block per post type |
| `upload_dir.php`      | Path and URL of the CMS upload directory (`htdocs/up_dir`) |
| `database/*.yaml`     | Table definitions for `fegg-cli migration` |
| `define.php`          | Optional. Project constants, loaded right after the core starts (web and CLI) |
| `fegg_update.php`     | Optional. Repository used by `fegg-cli core:update` (see [Updating the core](./update.mdx)) |

Any other file in `site/config/` can be loaded with [`$this->loadConfig()`](../basic/others/config/loadconfig.mdx). A file with the same name as one in `core/config/` (for example `validation_error_message.php`) replaces the core's file.
