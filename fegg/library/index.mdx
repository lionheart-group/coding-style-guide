# About Extension libraries

Fegg's goal is lightweight and less typing, so the controller base class only has the minimum required functions. Additional functions are provided as library classes in the core (`htdocs/_fegg/core/src/`).

## How to use

Every library is a namespaced class that is loaded by the autoloader. Import it with `use` and create it with `new`.

```php title="Controller"
<?php
namespace Site\Controller;

defined('FEGG_CORE_DIR') || exit;

use Fegg\Tool\Mail;
use Fegg\Validation;

class Contact extends Controller
{
    public function post()
    {
        $validation = new Validation();
        $validation->required('mail', $this->in('mail'), array('@required', 'Email'));

        if (!$validation->isError()) {
            $mail = new Mail('Mail subject', 'Mail body');
            $mail->send($this->in('mail'), 'Sender name', 'from@example.com');
        }
    }
}
```

:::note

Fegg 4 code such as `$this->getClass('Tool/Mail')` still works in Fegg 5 through `Fegg\Legacy`, but every use is written to the PHP error log as `Fegg deprecated: ...` and it will be removed in Fegg 6. Replace it with `new`.

| Fegg 4 | Fegg 5 |
| --- | --- |
| `$this->getClass('Validation')` | `new \Fegg\Validation()` |
| `$this->getClass('Tool/Mail', $subject, $body)` | `new \Fegg\Tool\Mail($subject, $body)` |
| `$this->getClass('Tool/Upload')` | `new \Fegg\Tool\Upload()` |
| `$this->getClass('ReCAPTCHA', $secret)` | `new \Fegg\Captcha\ReCAPTCHA($secret)` |
| `$this->getClass('DB_pdo')` | `new \Fegg\Database\Pdo()` |

The same applies to the other `Tool/...` classes (`Tool/File`, `Tool/RSS`, `Tool/Trim`), which became `Fegg\Tool\File` and so on. `Tool/Date` and `Tool/OEmbed` are removed: use PHP's `DateTimeImmutable` (see [Dates and time zone](../basic/controller.mdx#dates-and-time-zone)) and [Embed](./embed/index.mdx).

:::

## Project libraries

Put your own classes in `htdocs/_fegg/site/src/` with the `Site\` namespace. They are autoloaded in the same way.

```php title="htdocs/_fegg/site/src/MyLib/Foo.php"
<?php
namespace Site\MyLib;

defined('FEGG_CORE_DIR') || exit;

class Foo
{
}
```

```php title="Controller"
use Site\MyLib\Foo;

$foo = new Foo();
```

## External Libraries

These libraries are bundled in `htdocs/_fegg/core/vendor/` and autoloaded.

- [PHPMailer](https://github.com/PHPMailer/PHPMailer) (7.2)
  - Used by [Mail](./mail/index.mdx). Namespace `PHPMailer\PHPMailer`
  - A failed send throws `PHPMailer\PHPMailer\Exception`

JSON documents are handled with PHP's own `json_encode` and `json_decode`.

## YAML

YAML is read and written by the core's own `Fegg\Yaml`, without a library (Fegg 4 bundled Spyc, which is no longer maintained). The table definitions use it, and so can the project:

```php
use Fegg\Yaml;

$data = Yaml::parseFile(FEGG_SITE_DIR . '/config/shops.yaml');   // array
$text = Yaml::dump($data);                                        // YAML that reads back as $data
```

It reads YAML written by hand:

- block mappings and lists, with lists also at the indentation of their key;
- `[a, b]` and `{a: 1}`, also over several lines;
- `|` and `>` text, with `-` / `+` and an indentation indicator;
- single and double quoted text with every escape, plain text over several lines, comments.

Values follow YAML 1.2: `null` / `~`, `true` / `false`, integers (also `0x`, `0o`), floats (also `.inf`, `.nan`). `yes`, `no`, `on`, `off` and numbers with a leading zero (`014`) stay text.

Anything else is refused with `Fegg\YamlException`, whose message names the file and the line: anchors and aliases (`&`, `*`), merge keys (`<<`), tags (`!`), directives (`%YAML`), complex keys (`?`), several documents in one file, tabs as indentation. It is never read differently.
