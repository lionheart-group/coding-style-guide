# Introduction

> Providing some functions for processing image (especially image crop)

`Fegg\Tool\Trim` resizes and crops JPEG, GIF and PNG images with the GD extension. JPEG images are rotated according to their Exif orientation.

## How to use

Import `Fegg\Tool\Trim` and create it with `new`. Set the source image and the output path with [Trim::setImage](./methods/setimage.mdx), resize it with one of the `resize*` methods, then save it with [Trim::create](./methods/create.mdx) or send it without saving with [Trim::output](./methods/output.mdx).

```php title="Controller"
<?php
namespace Site\Controller;

defined('FEGG_CORE_DIR') || exit;

use Fegg\Tool\Trim;

class Thumbnail extends Controller
{
    public function index()
    {
        $trim = new Trim();
        try {
            $trim->setImage('path/to/image.jpg', 'path/to/thumbnail/300_300.jpg');
        } catch (\RuntimeException $e) {
            http_response_code(404);
            $this->halt('Not Found');
        }

        $trim->resizeTrim(300, 300, 'm');
        if ($trim->create()) {
            // Output the saved image to the browser
            $trim->view();
        }
        $this->halt();
    }
}
```

:::note

[Trim::setImage](./methods/setimage.mdx) throws a `\RuntimeException` when the source file is missing, is not a JPEG, PNG or GIF image, or the output path does not end with `.jpg`, `.jpeg`, `.png` or `.gif`. (Fegg 4 stopped the script with `exit`.)

:::

## Images of the CMS in other sizes

The images uploaded in the CMS are shown in other sizes through URLs such as `/up_dir/image/12/i-300_200.jpg`, built by the `getImageUrl` modifier (`{{ $page.data.image_id|getImageUrl:300:200 }}`).

```
/up_dir/image/{id}/{type}-{width}_{height}.{jpg|png|gif}
/up_dir/image/{id}/{type}-{width}.{jpg|png|gif}
/up_dir/image/{id}/{type}.{jpg|png|gif}
```

The first time a size is asked for, there is no such file, so the request reaches `Fegg\Controller\Up_dir::image()`, which makes it with this class and saves it at that path. From then on the web server sends the saved file.

| type | Method | Result |
| --- | --- | --- |
| `i` | [Trim::resize](./methods/resize.mdx) | Within the size, keeping the ratio |
| `c` | [Trim::resizeFill](./methods/resizefill.mdx) | Exactly the size, the empty area white or transparent |
| `f` | [Trim::resizeForce](./methods/resizeforce.mdx) | Stretched to the size |
| `lt` `t` `rt` `l` `m` `r` `lb` `b` `rb` | [Trim::resizeTrim](./methods/resizetrim.mdx) | Fills the size, keeping that part of the image |

A missing width or height is the original one. A name that is not one of these (`x-10.jpg`, `I-10.JPG`), an unknown image ID or a file that is not an image is a 404.

Two settings of `htdocs/_fegg/site/config/upload_dir.php` keep anyone from filling the disk or the memory with sizes:

| Key | Default | Remarks |
| --- | --- | --- |
| `image_max` | 2000 | Largest width or height that can be asked for. A larger one is a 404 |
| `image_cache_max` | 50 | How many sizes of one image are saved. Past that, new sizes are made for each request ([Trim::output](./methods/output.mdx)) and not saved |

```php title="htdocs/_fegg/site/config/upload_dir.php"
$upload_dir['image_max']       = 2000;
$upload_dir['image_cache_max'] = 50;
```

A project whose `upload_dir.php` does not have them uses these defaults.
